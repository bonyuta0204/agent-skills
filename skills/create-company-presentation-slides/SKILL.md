# Create Company Presentation Slides

## この skill の目的

この skill は、社内向けスライドを「見た目から作る」のではなく、**伝える内容の芯を先に固めてから資料化する** ためのものです。

特に次のような資料に向いています。

- キックオフ
- 方針共有
- 振り返り
- 社内ナレッジ共有
- チーム向けの期待値合わせ

この skill の主対象は、**骨子整理とスライド原稿づくり** です。PPTX が必要な場合だけ、最後に `PowerPoint` skill を使って PowerPoint 化します。

## 基本方針

- いきなり PowerPoint を作り始めない
- 最初に audience と message を絞る
- 1 枚 1 メッセージを守る
- 文章ではなく、発表スライドとして読める短い言葉にする
- Markdown で流れが通ってから PowerPoint に送る

## 進め方

### 1. 先に擦り合わせる

最初に、次の 3 点を必ず詰める。

- 誰に向けた話か
- 今回いちばん変えたい認識や行動は何か
- 最後に残したい一文は何か

必要なら次も確認する。

- 発表の場: キックオフ / 定例 / 勉強会 / 振り返り
- 聞き手の前提知識
- 話す時間
- すでに決まっているメッセージや避けたいトーン

この段階では full draft を急がず、短い質問で前提を絞る。

### 2. まず骨子を Markdown で作る

擦り合わせた内容をもとに、Markdown で資料の骨子を作る。

- 見出しだけで流れが伝わる状態を先に作る
- 各スライドに「何を言いたいか」を 1 行で置く
- 詳細な本文や見た目の話はまだ入れすぎない

フォーマットは [references/slide-markdown-format.md](references/slide-markdown-format.md) を使う。

### 3. スライド原稿に落とす

骨子が固まったら、各スライドを発表向けの短い原稿に直す。

- 1 枚 1 メッセージ
- 2〜3 行で言い切る
- 説明より断定を優先する
- 強調したい語だけを太くする、または色を変える前提で書く
- 箇条書きを増やしすぎず、聞き手が一目で理解できる粒度にする

必要なら、各スライドに次も添える。

- 補足メモ
- 話すときの口頭説明
- 図解やカード配置などの visual hint

### 4. PowerPoint が必要なときだけ仕上げる

Markdown の原稿が固まってから、必要なら `PowerPoint` skill を使う。

- 既存テンプレートがあるならそれを優先する
- まず Markdown を確定させてから PowerPoint に流し込む
- PowerPoint 側では story を変えず、見た目の整形に集中する

ユーザーが骨子だけ欲しい場合は、PPTX まで進めない。

## スライド文体ルール

- タイトルだけで 1 枚の意味が分かるようにする
- 1 枚に複数の論点を詰め込まない
- 長い説明文より、短い断定文を優先する
- 抽象語だけで済ませず、必要なら具体例を 1 つ置く
- 相手を責める語り口より、次に何を揃えるかが伝わる語り口を優先する

次のような崩れ方を避ける。

- 何を言いたいスライドか分からない
- 説明文が長く、読まないと意味が伝わらない
- 1 枚に現状、原因、対策を全部詰め込む
- PowerPoint 上の見た目調整で message まで変わってしまう

## 出力

返却は、原則として次の順で行う。

1. 擦り合わせで確認した前提
2. Markdown の骨子
3. スライド原稿
4. 必要なら PowerPoint 用の handoff、または PPTX
